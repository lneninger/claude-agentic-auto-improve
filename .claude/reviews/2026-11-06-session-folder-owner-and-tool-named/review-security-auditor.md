# Security Audit: issue #271, per-user session parent and codegraph-tool-named message

**Reviewer:** security-auditor, 2026-11-06
**Contract:** `.claude/concepts/2026-11-06-session-folder-owner-and-tool-named.md` (approved)
**Scope:** the uncommitted diff in `.claude/worktrees/20261106-bug-271-windows-session-owner-check`, focusing on
`.claude/addons/codegraph/hooks/codegraph-first-guard.py`, `codegraph-turn-tracker.py`, `codegraph-turn-reset.py`,
`.claude/hooks/_project_paths.py`, `.claude/scripts/_claude_paths.py`, `.claude/scripts/auto_improve_finish_install.py`.
**Method:** I read the code and ran read-only, offline probes on Python 3.12.10 (Windows). The only things the probes
touched were `nt._getfullpathname` (no I/O), `os.lstat` on local drives, and `lstat`/`mkdir` attempts under a base folder
that does not exist in `%TEMP%\sa271`. Nothing ran against a network host.

## Medium

- **M1. The Windows Remote rule misses device paths that resolve to UNC paths and mapped drives written in device form.** `codegraph-first-guard.py:294-298` (the same code is in the tracker at about `:148-152` and in reset at `:148-152`)
  **Exploit scenario:**
  1. Someone can set the victim's `LOCALAPPDATA` (threat (a): environment manipulation, for example a launcher, a wrapper script, or a project settings `env` block). They set it to `\\.\C:\..\UNC\attacker\share`.
  2. `_remote_host` reads the raw text and returns `?c:`, the local-drive form. Because the host is not None, `_own_spellings` skips `realpath`. `session_parent_base` returns the value as a local base. Probe: `('\\\\.\\C:\\..\\UNC\\srv\\s', None)`.
  3. Win32 collapses `..` inside a `\\.\` path when it opens the file, not only in `GetFullPathName`. Probe: `os.lstat(r'\\.\C:\..\D:\Dev')` opens `D:\Dev`. Also, `nt._getfullpathname(r'\\.\C:\..\UNC\srv\s\auto-improve-codegraph')` gives `\\.\UNC\srv\s\auto-improve-codegraph`. So every `lstat` and `mkdir` on the parent goes to `\\attacker\share` over SMB.
  4. Windows has no owner check, by design: the contract relies on the parent being local and per-user. So the attacker writes `auto-improve-codegraph\auto-improve-codegraph-<victim session>\turn.json` on the share and the gate opens (a Foreign marker, logged once). The attacker can also plant `ticket-*` files or a poisoned `availability.json`.
  - A second form: with `\\?\Z:\x` or `\\.\Z:\x`, where `Z:` is a mapped network drive, `_remote_host` gives `?z:` and `realpath` is skipped, so the rule never learns the drive is remote. The contract text says "a mapped drive that resolves to `\\server\share` is remote", and the Non-Goals say "the `remote` rule catches network paths, UNC and mapped drives alike". This code breaks both statements.
  **Impact:** an attacker who controls the environment can open the victim's gate (I-6 broken). Each hook call also sends an SMB connection, with the user's NTLM credentials, to a host the attacker names. That is the same class of leak #259 closed for `gitdir:`. Severity stays Medium only because the attacker must already control the environment.
  **Fix:** in `session_parent_base` on Windows:
  (1) refuse any device-path base (`\\?\`, `\\.\`) that contains a `..` segment, the same "climbs" rule `_hop_allowed` uses;
  (2) also judge `_remote_host(nt._getfullpathname(raw))`, which does no I/O and shows Win32's own collapse;
  (3) for the `?<letter>:` form, judge the drive letter too, either with `realpath` of the plain `X:\…` form or with `GetDriveTypeW == DRIVE_REMOTE`. The simplest choice is to treat every device-path base as `remote` except `\\?\<letter>:\` with no `..` and a fixed (non-remote) drive.
  Add table rows for `\\.\C:\..\UNC\h\s`, `//./C:/../UNC/h/s`, `\\.\C:\..\..\UNC\h\s` and a patched mapped `\\?\Z:\`. Keep the three copies in parity.

- **M2. A lone surrogate in the banner text sends `block()` into the I-4 catch-all, so the call is allowed.** `codegraph-first-guard.py:1168-1172` (`sys.stderr.reconfigure(encoding="utf-8")` then `print`)
  **Exploit scenario:** `reconfigure(encoding="utf-8")` changes the stderr error handler from `backslashreplace` to `strict`. Probe: `errors before: backslashreplace`, `errors after: strict`. When any text in the banner holds a lone surrogate, `print` raises `UnicodeEncodeError` before `sys.exit(2)`. The exception leaves `main()`, the catch-all at `:1277-1279` exits 0, and the call is allowed. There are two routes, both reproduced end to end with steps 4-6 patched so they cannot allow:
  1. **Environment route, new in this change:** `LOCALAPPDATA` holds `\udc80`. The verdict is `cannot-create`, the guard reaches the `session-state-unusable` banner, and that banner prints the parent path. Result: `internal error (failing open): 'utf-8' codec can't encode character '\udc80' ... EXIT 0`. The fail-closed state this contract adds therefore fails open.
  2. **Tool-input route, already present before this change:** a Grep or Glob `pattern`, or a Read `file_path` stem, holds `\ud800`. Claude Code's JSON escapes come back from `json.loads` as lone surrogates. `cg_suggestion` puts the text in the `source-target` banner. Result: `EXIT 0`. The party the gate is meant to stop (the agent) controls this input.
  **Impact:** the fail-closed promise (I-6, "a broken parent can only give a block") and the `source-target` gate can both be bypassed without touching the session folder. The contract's I-6 exclusion ("the I-4 catch-all, reached only by a defect outside the verdict function") covers this case, but only on paper: this is that defect, and anyone can reach it.
  **Fix:** use `sys.stderr.reconfigure(encoding="utf-8", errors="backslashreplace")` in `block()` and `announce()`. Also wrap the `print` and `log_event` in `block()` in `try/finally` so that `sys.exit(2)` always runs. Add rows: a surrogate in `LOCALAPPDATA` gives exit 2 with `session-state-unusable`, and a surrogate in a Grep pattern gives exit 2 with `source-target`.

## Low / Informational

- **L1. POSIX check-then-use race when the base folder is writable by others.** `codegraph-first-guard.py:948-951` (`session.resolve()` then path-based `lstat` and `open`). The verdict checks the parent's owner and mode and then drops them; every later operation re-walks `<base>/auto-improve-codegraph/...` by path. If the base can be written by another user and has no sticky bit (for example `XDG_CACHE_HOME` pointing at a group-writable shared folder), that user can loop `rename(parent, x); mkdir(parent); plant turn.json` and win the window between `resolve()` and `has_plain_file(MARKER_NAME)`. That opens the gate. The contract scopes the base to existence, text and remote checks, and lists "a shared local folder they chose" as a Non-Goal. Still, the Non-Goal's claim that "the owner and mode checks still catch a planted parent" only holds against planting done before the check. **Fix (hardening):** on POSIX, also refuse a base with `st_mode & 0o022` and no sticky bit (`S_ISVTX`) when the base is not owned by the user. Or open the parent once with `O_DIRECTORY|O_NOFOLLOW` and use `dir_fd` for the later operations.
- **L2. The Foreign-marker stamp is not authenticated.** `codegraph-first-guard.py:1210-1223`. Any process running as the user, the agent's own Bash tool included, can write a fully stamped `turn.json` and open the gate with no log record. The contract (Q4, I-6) accepts this: the stamp detects, it does not decide. Log flooding is bounded: one record per session, and the flag is written only after `log_event` did not return False. Log injection is not possible: `_error_log.py:129` writes the record with `json.dumps`, which escapes control characters, and the `cause` values come from a closed set. If `logged-foreign-marker` exists as a folder, `has_plain_file` is False and `create_once` answers `exists`, so the notice is printed and logged on every call. Only the user's own processes can create that folder, so this is a nuisance, not an exploit.
- **L3. Raw environment text and OS error text go into stderr banners.** `_base_shown` (`:302-306`), `unusable_lines` (`:1056`), and the `detail` text of `check-failed` (`:372`) put the `LOCALAPPDATA`, `XDG_CACHE_HOME` or `HOME` value, and exception text that contains it, into the stderr the model reads. Newlines and ANSI escapes are kept, so a hostile value could forge lines in the banner. Only someone who controls the environment can do this. The tracker and reset lines (I-8) do the same. Folder names are fixed and the session key is limited by `_SESSION_ID_RE`, so neither can inject. **Fix:** print `ascii()` or `repr()`-style escaped paths in the problem lines.
- **L4. The codegraph-tool-named message echoes settings entries verbatim.** `auto_improve_finish_install.py:2511-2519`. `entry` is any string in a settings layer's `permissions.allow` that starts with `mcp__codegraph__`. With `_render_text` (text mode), a project `settings.json` entry holding a backtick, a newline and text can close the code span and forge lines such as a fake "One step fixes it: run …" instruction. Raw echo already existed before this change; the new multi-line, backtick-framed layout makes a forged line indistinguishable from a real one. JSON mode escapes it. **Fix:** escape control characters and backticks in `entry` (for example `json.dumps(entry)[1:-1]`) and cap its length.
- **L5. The reset hook's "the gate stays shut" line can be false after a transient verdict.** `codegraph-turn-reset.py:433-439`. If the verdict is unusable at reset time (for example a transient `check-failed`) and usable again at the next guard call, the previous turn's own marker survives, and the gate opens in a turn where CodeGraph was never called. Only the user's own state is involved, so this is a correctness issue, not an exploit.
- **L6. The bridge can export `worktree_own_root = None`.** `_claude_paths.py:201-204`. When a future helper declares `TREE_HOP_REFUSAL = True` but renames `worktree_own_root`, the Hop proof is True and `worktree_own_root` is bound to `None`, so callers get a `TypeError` instead of the inline copy. Only an availability risk. **Fix:** `worktree_own_root = _native_own_root if TREE_HOP_REFUSAL and callable(_native_own_root) else _inline_worktree_own_root`.
- **L7. Other `evaluate()` exceptions still reach the catch-all.** For example, `json.load` of a deeply nested `availability.json` raises `RecursionError`, which `read_json` does not catch (it catches only `OSError` and `ValueError`). Only the user's own processes can write that file, and such a process can just as easily write `turn.json`. Listed so the "never the catch-all" claim is not read as covering the whole of `evaluate()`.

## Attack items with no finding

- **(a) Shared TMP:** no hook calls `gettempdir` any more (grep is clean). The system temp folder is never read, written or pruned.
- **(a) A parent pre-created by someone else (POSIX):** caught by the `st_uid` check at `:363-367`, which gives `foreign-owner` (a denial of service at worst, with a named fix). The `0o077` mode check also catches access granted through POSIX ACLs, because an ACL mask shows in the group bits.
- **(a) Junction, symlink or reparse point at the parent or the Session folder:** `lstat` plus `S_ISLNK` or `FILE_ATTRIBUTE_REPARSE_POINT` gives `link` or `session-link`. A base that is a junction to UNC is caught by `realpath`.
- **(a) 8.3 short names and case-insensitivity:** every check runs `lstat` on the same string that is later opened. The one string comparison, in `_remove_folder`, compares two `realpath` forms. No bypass.
- **(a) `\\?\UNC\…`, `\\.\UNC\…`, `\\?\GLOBALROOT\…`, `\\;LanmanRedirector\…`, `//srv/s`, `\\?\Volume{…}`:** all give `remote` (probed).
- **(a) `\??\UNC\…`:** `realpath` touches the share and then either gives `remote` (share reachable) or `cannot-create` (unreachable). This fails closed, but the touch happens during the check; the M1 fix (judge `_getfullpathname` first) also covers it.
- **(b) Pruner:** it lists only the usable parent (I-9). It skips links and reparse points, foreign `st_uid` (POSIX), unknown names and subfolders. Before each `os.remove` it re-checks the file and the folder, and it removes the folder only with `rmdir`. Removing a hard link deletes only the link. A junction inside the parent is kept and its target is untouched. I found no path that deletes outside the caller's own parent.
- **(c) Fail-closed:** the Stateless session makes no filesystem calls (`ensure_folder`, `has_plain_file` and `create_once` all check `problem` first). `announce()` returns before any flag is created. When the step 8 write fails, `resolve()` runs again and the result is never an allow. The only routes to an allow from an unusable state are steps 4-6 (documented) and the catch-all (M2, L7).
- **(e) Hop proof accepting the 0.15.2 shape:** `_hop_allowed` first appears in `3780c2f` (0.15.2), in the same commit as the commondir normpath fix (`git log -S_hop_allowed`). No released helper has the shape without the refusal. Faking the shape means writing a `.py` file into the hooks folder, and that already runs arbitrary code. No downgrade.
- **(f) Settings content:** see L4. The text goes only into the message, never into a path or a command.

## Verdict

**pass-with-conditions.** M1 and M2 must be fixed before merge, because each breaks a guarantee the contract states:
- M1 breaks the Remote rule ("network paths, UNC and mapped drives alike"), and brings an NTLM leak with it.
- M2 breaks I-6 (a broken parent gives only a block).

Both fixes are small, and each needs the matching rows in all three hook copies. L1-L7 are hardening items.
