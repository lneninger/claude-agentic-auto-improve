This review reproduced every one of them (Evidence), so the gap is closed for this contract, and nothing needs to change before the landing.
- **F2 [warning] Block 1 passed on two Run-list suites that did not exit 0, instead of stopping for an amendment.** Location: the contract's block 1 CONSTRAINTS ("Run (all exit 0): … test_land_contract.py … test_plugin_manifests.py"; "If the contract mis-predicts an exit code, stop and ask for an amendment"). #414 reports `test_land_contract` 1 failure and `test_plugin_manifests` 2 failures, called "not from this change". I reproduced both on the unchanged merge base `9fdc6db`. `TestContainmentScanner.test_the_real_tree_holds_no_merge_outside_land_contract` finds `('skills/ship/SKILL.md', 'gh-pr-merge')`, and `test_plugin_manifests` fails "every --flag the skill names exists in the script's parser" (`--fix`) and the codegraph cut-over guard hash label. They are pre-existing master failures, not regressions, so the code is not at fault. The contract mis-predicted the exit codes, and the block should have halted for an amendment rather than reporting past it. Neither suite is a configured landing step, so the landing's P8 is not affected.
- **F3 [nit] The full pin's refusal assertion has no control of its own.** Location: `.claude/scripts/tests/test_repo_consistency.py`, `ManifestCountPinTests.test_manifest_description_counts_match_oracles`. Deleting `self.assertEqual(refresh_refusals(...), [])` fails no test on today's tree. The route rows judge `manifest_pin_problems`, a test-side helper the real pin does not call. With a planted refusable description, the deletion is still caught by `ManifestPinRouteTests.test_the_real_manifests_have_an_empty_refusal_list`, which repeats the same assertion over the real manifests. The guarantee holds through that duplicate. A future edit that removes the duplicate would leave it unguarded. No change is required.
- **F4 [nit] A whitespace-only `MANIFEST_PIN_BASE_REF` defers the pin.** Location: `resolve_pin_context` / `count_pin_deferred`. With the env source, the base `" "` is "set and non-empty", so it differs from the default and the pin defers for any head. This follows the contract's wording (`env`: "set and non-empty"), and GitHub never sends a blank `base_ref` on `pull_request`. The I-7 line would show `base  ` in the log. Not a defect against the contract.
