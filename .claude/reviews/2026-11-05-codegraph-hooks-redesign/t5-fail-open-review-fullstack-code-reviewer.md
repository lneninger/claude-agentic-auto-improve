## Findings

- **F1 [WARN] (Soft): the four accepted terms are not in `VOCABULARY.md`.** The contract's Business Concept lists Transcript turn state, Live plan, Shadow decision and Shadow record as "New terms (Universal, promoted at review)". None of the three registries names them. No block lists a registry in its Files to touch, and this block may write only its artefact, so the entries are not written here. Proposed Universal entries, to append at the landing, whose version raise covers the registry change:
  - **Transcript turn state** *(2026-11-05, issue #261)*: `open`, `closed` or `unknown:<cause>`, read from the tail of the session transcript. It is `open` when an assistant `mcp__codegraph__*` tool use follows the last entry positively identified as a human prompt. Any `unknown:*` (no-transcript, unreadable, parse-error, window-exceeded, time-exceeded, rewritten, subagent) never blocks.
  - **Live plan** *(2026-11-05, issue #261)*: the `codegraph` guard's decision computed as a pure function: the decision, the reason and the state effects it would apply (availability cache write, ticket delete or write), with none applied. `main()` applies them after the shadow.
  - **Shadow decision** *(2026-11-05, issue #261)*: the Live plan recomputed with the Transcript turn state in place of the Turn marker. It is logged, never enforced, and its effects are discarded.
  - **Shadow record** *(2026-11-05, issue #261)*: one line per guarded call in `<CLAUDE_PROJECT_DIR>/.claude/logs/codegraph-shadow.jsonl`. It holds classes, booleans and hash prefixes only, and pairs the live and the shadow decision with an `outcome`.
  - The New Mechanism **Shadow decision log** is *not* promoted. The contract says "promote when a second guard adopts it" (JOURNAL 2026-10-28), and only one guard uses it.
- **F2 [INFO] (Safe): S-1 says the shadow "recomputes neither" verdict. The shadow does compute availability when the Live plan stopped before step 4.** When live allows at step 2 (marker present) and the transcript reads `closed`, `base.availability` is `None`, so `_plan` calls `availability_plan` read-only (`:937-943`). SH-G2c tests this and confirms no write. The divergence is justified, because there is no live verdict to reuse. The S-1 sentence should read "reuses them when the Live plan computed them, else computes them read-only" at the cut-over.
- **F3 [INFO] (Soft): the 50 ms Shadow time budget bounds only the transcript read, not "the whole shadow section".** The deadline is checked inside `read_transcript`. After it, `_plan` (classification, plus the F2 availability read of up to three settings files and two `.claude.json` files), the cursor write and the log append run without a check. On a live block, availability is reused, so only classification and two small writes remain. On a live allow, a host kill at timeout still allows (t1 point f). So no exit code changes in practice. Suggested for the cut-over: skip `_plan`'s availability step, or record `time-exceeded`, once the deadline has passed.
- **F4 [WARN] (Soft): `test_plugin_text_scans.py` fails on HEAD.** `test_no_shipped_file_names_an_individual_codegraph_tool` lists the five t1 fixtures, the fixtures `README.md` and `test_codegraph_shadow.py`. t3 reported it, t4 did not clear it, and it is still red: 18 passed, 1 failed. CI runs only `version-bump.yml`, so this does not stop a merge, but the landing must not ship a red suite. Fix before the landing: add the fixtures folder and `test_codegraph_shadow.py` to the test's documented exception list (they quote host transcripts and tool names on purpose), or rename the tool names in them. (`test_plugin_manifests.py` fails only its merge-base version row, 189/1. That is expected under the Parent Branch Delivery Rule: the landing raises the version.)
- **F5 [INFO] (Safe): a ticket gone at apply now allows, where #259 fell through to a fresh block.** `apply_state` keeps the planned `retry-escape-used` when `os.remove` fails (`:986-990`). #259 wrote a new ticket and blocked. The contract sanctions this (G-2, "it can only allow"), and SH-G2b covers it. Two consequences are not in the contract: two identical parallel retries both log a `retry-escape` record, and a ticket that cannot be deleted (a sharing violation) allows every identical call until the next prompt. Both only allow.
- **F6 [INFO] (Safe): a cold window holding a CodeGraph use but no boundary answers `open`, not `window-exceeded`.** Read limits say "A cold window with no boundary is also `window-exceeded`". The code leaves `turn` as `None` only when the window held neither kind (`:1282`, `:1328-1331`). The answer is sound: no prompt after the use means the use belongs to the current turn. It errs toward open. Record it in the contract at the cut-over.
- **F7 [INFO] (Safe): t4 edited `README.md` (two case counts, 385 to 394), which is not in block 4's Files to touch.** This is a forced, mechanical follow-on: `test_plugin_manifests.py` INV-15 pins the count. There is no behaviour drift. `.claude/area-mapping.json` has no areas, so `derive_area.py` returns `uncategorized` and the area comparison is vacuous.
- **F8 [INFO] (Safe): G-1 corner cases that do not change the outcome.** (a) With the marker present, classification no longer runs. A classification that would have raised (formerly the outer handler's stderr line `internal error (failing open)`, exit 0) is now a silent exit 0, so stderr differs only in that unreachable-in-practice case. (b) `_import_helper` does not honour a `sys.modules[name] = None` import block the way `import` does. No Baseline row and no install uses that. (c) `shadow_ms` and the budget use `time.monotonic()`, which ticks at about 15.6 ms on Windows (from t3). `time.perf_counter()` would resolve it.
- **F9 [INFO] (Safe): one SH-L5 assertion is a tautology.** `parsed + malformed >= parsed` (`test_codegraph_shadow.py:773`) is always true. Only `parsed <= writes` tests anything. The test stays within the contract's "interleaving-independent only" rule. Replace it with "every non-blank line was parsed or counted malformed" against the line count.

## What was NOT checked

- #259's own code and tests (merged at `979ec08`): they are the Baseline, reviewed under #259.
- The bench was not re-run; check 8 rests on the t3 table and its spread notes. The live sessions of t1 were not repeated; check 9 rests on the t1 artefact and on SH-E4 reproducing its classifier output from the committed fixtures.
- POSIX: every suite ran on Windows only. The POSIX-only paths (`st_uid` ownership in step 0, `O_NOFOLLOW`) were read, not run.
- A host process holding the transcript open in a share mode that conflicts with the shadow's `open(path, "rb")`. Python on Windows opens without `FILE_SHARE_DELETE`, so a host rename or replace during the 50 ms read could fail. No such host behaviour was seen in t1 (compaction appends).
- A hung `os.stat` / `open` on an offline network transcript path. The time budget cannot bound a blocking system call, and a host kill would then turn a live block into an allow (t1 point f). This sits under the contract's Uncertain Assumptions.
