# Plain Language Rule

Write for the user and for anyone new to the project. A person who did not watch the work must be able to follow every message.

**Explain every named element**: mention nothing by name without saying, the first time, what it is. Say what a file, class, tool or command is and what it does for this task. Example: write "the intake command, which opens a separate checkout for the change", not only the command's name. No automatic checker can catch a break of this rule, so it depends on you alone.

**Use a name, not a number**: do not label a step, a count or a finding with a bare number. Say what the thing is called.

**Write short forms out**: spell out each short form once, with the short form in brackets right after it.

**One idea per sentence**: split any sentence that carries two points.

**Keep sentences to thirty-five words or fewer**: aim for under thirty.

**Fewer than three long dashes in a sentence**: use a full stop or a comma instead.

**Questions a newcomer can answer**: name the real things involved and say what goes wrong in plain terms. Never ask about something only you have seen.

The end-of-turn writing checker catches some of these breaks. It cannot catch the first one.
