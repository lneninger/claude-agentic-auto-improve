# Recommendations, Not Question Batches

Lead with a recommendation. State each finding with its effect and what you recommend, so the user can accept it with one word.

Never hand the user a batch or a menu of questions. A list of open choices pushes the analysis back onto them.

Ask a question only when a skill's gate requires asking the user, for example the design skill's Open Questions. Then ask one question at a time, each carrying its own recommendation.

A project's own instruction, or a skill's explicit gate, wins over this agreement.
