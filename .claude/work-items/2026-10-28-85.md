# Add the test-resource lifecycle owner to the unit-testing skill

Raw invocation: `https://github.com/lneninger/claude-agentic-auto-improve/issues/85`

## Problem statement
The plugin's `unit-testing` skill says every resource a test run creates must be removed afterwards, pass or fail. It gives no design for how a project meets that duty, and its database bullet still tells authors to build their own disposable connection string. An author following the plugin alone can write a hand-built create-and-drop lifecycle in each test. The StockToolScalpingMachine project solved this with one object, the test database owner, which names, creates, sets up and removes every test database, plus a source-scan test that fails any hand-built database lifecycle. That doctrine lives only in that project. The issue proposes generalising the owner from databases to any resource a test run creates and making it a plugin rule.

## Acceptance criteria
Taken from the issue body:
- [ ] A section in the `unit-testing` skill (or a reference file it links) states the owner contract: one object creates, names, sets up and removes the resource, and callers never do it by hand.
- [ ] It names the code standards the owner follows, each with its reason: single responsibility, a setup step passed in (strategy), a fixed create, set up, remove order (template method), a factory for disposable names, dependency inversion on the managed thing, open for extension and closed for modification.
- [ ] It states the learned rules: the disposable-name rule, the setup-failure policy (remove first, then rethrow or record), always dispose the owner, no step after the owner's setup in a test class's own setup, and a failed removal becomes a named notice, never a silent skip.
- [ ] It describes the source-scan guard and the runtime leftover check (count resources matching the disposable pattern after the suite and fail if any remain), and says what each cannot see.
- [ ] The skill's real-SQL bullet points at the project's owner, and says what to do when the project has none yet.
- [ ] `agents/senior-test-engineer.md` keeps its single boundary and gains at most one pointer line, or stays unchanged with the reason recorded.
- [ ] The plugin version is bumped as this repository's rules require.
