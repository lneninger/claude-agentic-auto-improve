# merge_direction.py cannot read sub-issues from gh 2.96 (object, not list)

## Problem statement
The merge-direction check refuses every pull request from an issue-linked branch with "unverifiable: the sub-issues of #N could not be read", because `_open_children` requires `subIssues` to be a list while `gh` 2.96 answers `{"nodes": [...], "totalCount": n}`. The same check runs inside the `gate-launch.py` hook, so no agent can open such a pull request.

## Acceptance criteria
- [ ] `_open_children` accepts both shapes: a plain list, and an object with a `nodes` list.
- [ ] A test covers the object shape with zero, one open and one closed sub-issue.
- [ ] An unreadable result (command failure, invalid JSON, missing field) still returns "unverifiable"; the check must not fail open.
- [ ] The fix is synced into projects that carry a copy of the script (ScalpingMachine first).

## Out of scope
- `land_contract.py`, which already reads the object shape.
