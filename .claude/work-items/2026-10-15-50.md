# Clean up worktrees and merged branches automatically once a work item is delivered

## Problem statement
When a work item is fully delivered, its worktrees and branches stay behind until a person removes them by hand. `/pr-merged` only offers the cleanup (its Step 6) and the offer is easy to leave open. In the delivery of issue #469 in lneninger/StockToolScalpingMachine three problems showed up: (1) the session stands inside the worktree it must remove, so the user had to run several lines from outside, which breaks the one-short-line rule; (2) a worktree may hold a link (junction) to another tree's `node_modules`, and removing the worktree before the link alone can delete the real folder; (3) `git branch -d` refuses a merged branch whenever the current branch is not the one it merged into, so the step needs an ancestor check against `origin/master` and then a forced delete only when that check passes.

## Acceptance criteria
- [ ] When the contract's completion condition is met (every sub-task has a record, the delivery is verified, and the contract status is `implemented`), cleanup runs without a manual step and leaves no worktree and no merged local branch belonging to the work item.
- [ ] Remote branches of the work item are deleted only if GitHub has not already deleted them.
- [ ] A test covers a worktree that holds a `node_modules` link: the link is removed alone and first, and the real target folder survives.
- [ ] A test covers a worktree with uncommitted or unpushed work: it is left alone, and the report names the files.
- [ ] A test covers a branch whose commit is not in `origin/master`: it is kept and the report says why.
- [ ] A branch is deleted only after an ancestor check against `origin/master` passes (forced delete is allowed only then).
- [ ] A worktree or branch that belongs to another session or another work item is never touched (test: a sibling item's worktree survives).
- [ ] The run prints a one-line report of what was removed and what was left, with a reason for each item left.
- [ ] When the session stands inside a worktree it must remove, the cleanup either runs from outside (moves out first) or hands the user exactly one script line, never several.

## Out of scope
- Cleanup of worktrees or branches of work items that are not delivered (open pull request, unmerged, or contract not `implemented`).
- Landing worktrees' own lifecycle in `land_contract.py` (already handled there).
- Syncing the change into other projects that carry a copy of the scripts: reported to the user at the end, not done here.
