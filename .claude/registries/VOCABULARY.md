# Business Concept Dictionary

> **Purpose:** one-paragraph definitions of every domain term used in concept contracts. Prevents agents and user from drifting on ambiguous language.
>
> **Rule:** a term enters this file the first time it appears in a concept contract. Ambiguous terms become **open questions** to the user in the contract — never guessed. Once the user confirms the definition, the data-architect appends it here.
>
> **Two tiers:** Universal (cross-project engineering vocabulary) and per-project domain vocabulary.

---

## Universal Vocabulary

- **CodeGraph** — the semantic knowledge-graph index of a codebase produced by the `codegraph` CLI. Stored at `<project>/.codegraph/codegraph.db`. The authoritative answer source for "where, who, what" questions about code. Exposed to Claude Code as a set of MCP tools (`mcp__codegraph__codegraph_*`). Established as the primary investigation tool by the CodeGraph-first protocol (`~/.claude/hooks/codegraph-first-guard.py`). NOT a documentation file or a memory store — it is a queryable graph rebuilt from source.
- **Symbol Node** — a vertex in the CodeGraph representing a code symbol (class, interface, method, property, field, function, module). Carries a stable id across runs, a name, a kind, and a source location. Operations: `codegraph_search` (find), `codegraph_node` (inspect).
- **Code Edge** — an edge in the CodeGraph between two Symbol Nodes representing a call, reference, inheritance, or containment relationship. Drives `codegraph_callers`, `codegraph_callees`, and `codegraph_impact`.
- **Investigation Turn** — the span between two `UserPromptSubmit` events. Within one turn, the CodeGraph-first gate opens after the first `mcp__codegraph__*` call (sentinel `<cwd>/.claude/.codegraph-used-this-turn` is created); the next `UserPromptSubmit` resets the gate by deleting the sentinel. This is the unit of "fresh investigation budget" enforced by the protocol.
- **Entity** — an object with identity that persists over time. Two entities with the same field values are distinct if their identities differ. Entities own their data and enforce their invariants.
- **Value Object** — an immutable shape defined only by its field values. Two value objects with equal fields are interchangeable. Has no identity. Used for things like Money, DateRange, Coordinates, TrailingStopState.
- **Aggregate** — a cluster of entities and value objects treated as a single consistency boundary for writes. The aggregate root is the only entity an outside caller may reference.
- **Domain Event** — an immutable record of something that happened in the domain. Past tense. Carries payload needed by downstream consumers.
- **Command** — an imperative request to change state. Present tense. May be rejected.
- **Port** — an interface declared by the domain that describes a dependency (e.g. `IMarketDataProvider`).
- **Adapter** — an implementation of a port that bridges to a specific technology (IBKR, backtest data, etc).
- **Invariant** — a rule that must always be true for an entity or aggregate to be in a valid state.
- **Projection** — a read-optimized shape derived from entities, used for queries and UI.
- **Saga / Process Manager** — a long-running coordination of multiple domain events toward a business outcome.
- **BatchedInQuery** — the approved pattern for EF Core queries that filter by a key set whose size may exceed the database's per-statement parameter limit (SQL Server caps at ~2100). The key set is split into chunks of ≤2000 and executed as one server-side query per chunk, with the results concatenated into a single materialized list. Callers supply a factory that turns a chunk into an `IQueryable<T>` and retain full control over `AsNoTracking()`, projections, and additional filters. Forbidden alternatives: (a) the naive `.Where(e => hugeSet.Contains(e.Key))` which generates an oversized `IN()` and fails with a TDS protocol error, and (b) the `.ToListAsync()` + in-memory filter workaround which defeats pagination and wastes memory on the full table.
- **Startup Task** — a unit of one-time, fire-and-forget work that runs at application startup in its own DI scope. Implemented as a class implementing `IStartupTask` (Domain port) with a `Name` property and a single `ExecuteAsync(IServiceProvider scopedProvider, CancellationToken ct)` method. Registered via `services.AddStartupTask<T>()`. A single `StartupTaskRunnerHostedService` (inheriting `BackgroundService`) executes every registered task once at startup, in registration order, with a fresh scope per task and centralised exception isolation. Replaces the ad-hoc `_ = Task.Run(async () => { ... })` pattern that silently swallows exceptions, captures scoped services against the root provider, and is impossible to test as a unit. Tasks check their own feature flags inside `ExecuteAsync` and early-return if disabled. Failures are logged with the task `Name` and do NOT cancel subsequent tasks. Tasks that MUST complete before the HTTP server accepts requests need a different mechanism (`IHostedLifecycleService.StartingAsync`) — the runner's `BackgroundService` base runs concurrently with the server.
- **Claude data root** — one candidate `.claude` directory in the ordered search space that every Claude path locator walks when looking for Claude *data* (registries, concept contracts, north-stars, the area map, the contract-accuracy ledger, the derived-scan cache). Produced by `claude_roots()` in `.claude/hooks/_project_paths.py`. Each root carries an implicit rank: rank 0 is the `.claude` directory under `$CLAUDE_PROJECT_DIR` (present only when Claude Code launched the process — **unset in a plain shell**), **rank 1 is `SELF_ROOT`** — the `.claude` directory the resolver module itself lives in — rank 2 is the one under `$PWD`, and rank 3 is the one under `$HOME`. Rank 1 exists because ranks 0 and 2 are both caller-controlled and both silently wrong when the caller is a plain shell in a subdirectory; the resolver ships *inside* the tree it searches, so its own location is the one rank a caller cannot get wrong. A root is *selected* by the first-that-**contains-the-sought-thing** rule, not by mere directory existence: `registry()` takes the first candidate for which the file `is_file()`, and `first_populated_dir(roots, pattern)` takes the first directory that actually holds a match for `pattern`. When no root holds it, the rank-0 (preferred, repo-shaped) candidate is returned so that a *writer* creates the file in the right place. Roots are never unioned — unioning would leak one checkout's contracts into another's inventory and into the accuracy ledger. Distinct from a **Claude runtime root** (`logs/`, `state/`), which resolves through `project_dir()` alone and has no `$PWD` fallback, because it holds machine-level runtime rather than repository content.

- **Plugin repository** — a sibling checkout holding the project-independent half of a Claude Code setup, so that a second project can adopt the same workflow without copying files by hand. It is a source to copy from. It is **not**, unless it also carries a plugin manifest and a marketplace entry, something the editor can load by itself: Claude Code's own plugin mechanism is the `enabledPlugins` and `extraKnownMarketplaces` pair in the workstation settings file, and a repository absent from both is a vendoring source rather than a package.
- **Vendored asset** — a file that lives in the plugin repository and is copied, unchanged, into a consuming repository. The consuming copy is committed, so the repository works when the plugin checkout is absent, and the sync tool is what keeps the two equal. Exactly one copy exists in the consuming repository, at its ordinary path — never a second copy in a subdirectory named after its owner.
- **Ownership tier** — the label that says whether a given setup file is owned by the plugin, and therefore replaceable on sync, or owned by the consuming project, and therefore never touched. Every setup file carries exactly one tier. The tier is recorded in `.claude/.sync-config.json` and nowhere else; a file that no tree's file list names is a local asset by default.
- **Sync direction** — which way changes may travel for one synced tree. Three values: `bidirectional`, `plugin-to-repo`, `repo-to-plugin`. It is a property of the tree, recorded once in the sync configuration, and never a property of an individual file. Every tree holds `bidirectional` today; the other two remain defined so a future tree can use one.
- **Vendored-asset drift** — the condition where a vendored asset and its plugin original no longer match. Detected by comparing content hashes of the two files **after normalising encoding** — folding line endings and stripping a leading byte order mark — never by comparing timestamps, because a checkout rewrites timestamps and an encoding convention rewrites bytes without changing meaning. A file present on one side and absent from the other is drift of its own kind and is reported as such; before 2026-09-12 it produced no signal at all. The qualifier is part of the term: the bare word *drift* already means generated output no longer matching its source in this project, and the two conditions are unrelated.
